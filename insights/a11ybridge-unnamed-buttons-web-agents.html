Small local AI agents almost never found a button that had no name, and one time in ten clicked the risky one

A11yBridge: what happens to small local language models acting as web agents when the control they need has an accessibility defect.

By Muzammal Hussain · 12 November 2026 · Research update

Many web agents read a page through its accessibility tree, the same list of roles and names a screen reader uses. If a button has no name, a screen-reader user cannot tell what it does, and neither can the agent. I built 168 fictional clinic pages, each with one target control, one risky look-alike and two neutral controls, and gave the same one-step task to five local models in English and in Roman Urdu: 1,680 calls in total.

Key findings

  1. No name, no click: a button with only an icon was chosen 3.1% of the time, and an image button with no alt text 3.8%, against 96.9% for the same button with its name.
  2. The risky look-alike got picked: on unnamed or generically named buttons, about one run in ten chose the dangerous neighbour, such as "Delete report" when asked to save the report.
  3. Visible text rescued the wrong role: a "button" built from a plain div was still found 94.4% of the time; an exact role-and-name script found it 0% of the time.
  4. Roman Urdu mostly did not change the outcome: three of fifteen model and element comparisons were clearly worse in Roman Urdu, one was better, and the other eleven included zero in their intervals.

Setup

Sixteen tasks (8 buttons, 4 links, 4 text fields) were each rendered with and without element-specific defects in two layouts, giving 168 pages. Chromium rendered every page with Playwright, and the model saw the page's accessibility snapshot as numbered lines. It had to reply with the number of the line to act on, or 0 if nothing fitted. The models were qwen2.5:3b, llama3.2:3b, qwen2.5:7b, mistral:7b and llama3.1:8b, run locally with Ollama at temperature 0. Each defect page was compared with the same task and layout without the defect.

The models failed in different ways. Faced with a button named only "Action", mistral:7b said nothing fitted in 75% of English runs, while qwen2.5:3b chose the risky look-alike in 44%. Saying "none" is the safer failure: the user can be asked, whereas a wrong click on Delete may not be undoable.

Roman Urdu instructions were clearly worse for llama3.2:3b on buttons (−14.6 percentage points, 95% interval −22.9 to −7.3), for mistral:7b on links (−17.5, −30.0 to −7.5) and for qwen2.5:3b on links (−10.0, −20.0 to −2.5), and better for llama3.1:8b on text fields (+12.5, +3.1 to +25.0). The other eleven comparisons had intervals that included zero.

What this means

For an agent that reads the accessibility tree, an unnamed control is invisible, just as it is to a screen-reader user. Fixing accessible names therefore helps two groups at once. For agents themselves, the risky look-alike result matters more than the miss rate: an agent that cannot find the right button should stop and ask, and a destructive action should never be taken on a guess.

Limitations

The pages are fictional, written by one person, with one defect at a time; real pages combine many. The task is a single element choice, not a full multi-step agent, and the model sees only the accessibility tree, not the screen. The models are small open models at default quantisation, with one answer per page. An agent finding a control is not evidence that the page is usable for people who rely on assistive technology.
